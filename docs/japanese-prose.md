# 日本語文章設計書

この文書は、**一文をどう書くか**の規約である。
`writing-style.md` が記事の構成と態度を決めるのに対して、こちらは文の骨格を決める。

適用範囲は本文だけではない。むしろ本文以外のほうが重要である。

| 対象 | 例 | 危険度 |
| --- | --- | --- |
| 一覧の一文 | `plays.ts` の `hook` | **最高** |
| 要約 | `summary`、章の `summary` | **最高** |
| キャプション・ラベル | `caption`、`note` | 高 |
| 記事本文 | `body.mdx` | 中 |

一覧の一文がもっとも危険なのは、**単独で読まれる**からである。
前後の文脈がないので、省略したものは復元されない。
本文なら前の段落が補ってくれるが、一覧では補われない。

過去の失敗は、すべてこの表の上二行で起きている。

---

## 1. 主語を省かない

日本語は主語を省ける。省けることと、省いてよいことは違う。

省いてよいのは、**直前の文と主語が同じで、かつ同じ段落にいるとき**だけである。
一覧・要約・キャプションでは、この条件が成立しない。常に書く。

```
悪い: 関を越えます。この場面は史料にも物語にもなく、能がつくったものです。
良い: 山伏に化けた一行が関を越えます。この詮議の場面は同時代の記録に見えず、
      「安宅」の作者による創作と考えられます。
```

```
悪い: 何も書いていない巻物を、朗々と読み上げます。そして家来が主君を殴ります。
良い: 山伏に化けた義経一行が、安宅の関で足止めされます。弁慶は白紙の巻物を
      勧進帳と偽って読み上げ、疑いを逸らすために、主君である義経を杖で打ちます。
```

悪い例は「誰が」を全部落としている。
読み手は、読み上げているのが弁慶であることも、殴られたのが義経であることも知らない。
書き手だけが知っている情報を前提にした文は、文として成立していない。

### 自己点検

書いた一文について、**「誰が？」と三回聞く**。
三回とも答えが文中にあれば通る。一度でも「書いてないが、常識で分かるはず」と思ったら書き足す。

---

## 2. 創作上の判断の主語は、人にする

これは1の特殊な場合だが、独立させる。このサイトの主題に直接かかわるからである。

```
悪い: この場面は、能がつくったものです。
良い: この場面は、「安宅」の作者による創作と考えられます。
```

能は芸能の名前であって、意志を持たない。決めたのは人である。
そして**誰が決めたのかを問うことが、このサイトの軸のひとつ**（思想軸「語る者・作る者・見る者」、FEATURE 11「誰が作ったのか」）である。
主体をぼかす書き方は、自分の前提を壊している。

### 見分け方

その動詞が、**意志のある人間にしかできない行為**かどうかで判断する。

| 動詞 | 主語 | 例 |
| --- | --- | --- |
| つくる・選ぶ・決める・移す・削る・書き足す・置き換える | **人**（作者、作者たち） | 「八島」の作者は後者を選びました |
| 描く・語る・扱う・持つ・示す | 作品でよい | 能は、合戦を勝敗の物語として扱いません |

作者不詳の曲が多い。その場合は「作者」「この曲の作者」でよい。
分かっているなら名前を出す（世阿弥、観世信光）。

複数の曲にまたがる傾向を述べるときは「作者たち」を使う。
『平家物語』は〜と語る、と同じ換喩なので、作品を主語にすること自体は禁じない。
禁じるのは、**一回の創作上の決定**を作品や芸能に帰属させることである。

---

## 3. 固有名詞を省略しない

### 初出はフルネーム

| 書かない | 書く |
| --- | --- |
| 静 | 静御前 |
| 業平 | 在原業平 |
| 知盛 | 平知盛 |
| 敦盛 | 平敦盛 |
| 秀衡 | 藤原秀衡 |

二度目以降は短くしてよい。ただし**一覧の一文はすべてが初出**である。

### 人名には一言の属性を添える

```
悪い: 追手が来ています。逃げる時間を稼ぐために、女が舞いはじめます。
良い: 吉野で義経を追う僧兵たちの前に、愛妾の静御前が進み出て舞いはじめます。
```

読者が辞書を引かないと読めない文を書かない。

### 地名は現在の都道府県を併記する

旧国名だけで位置が分かる読者は少ない。「信夫（福島市）」のように書く。

### 死者は、死者と分かるように書く

```
悪い: 後半でその同じ海から、自分が滅ぼした男が出てきます。
良い: 船出した一行を、壇ノ浦で滅ぼされた平知盛の怨霊が、
      波の上から薙刀を構えて襲います。
```

悪い例では、その人物が生きているのか死んでいるのかが分からない。
能では死者が舞台に出てくることが多い。**生死は必ず明示する**。
「霊」「亡霊」「怨霊」を省略しない。

## 4. 出典のない数値を書かない

上演時間を「約40分」「約90分」と書いていたことがある。
すべて10分刻みに丸まっていた。推定で置いた数字だった。

数値は、書いた瞬間に事実として読まれる。
**丸い数字が並んでいたら、自分の推定を疑う。**

書けないときは、書けないことと理由を書く。伏せるより誠実である。

> 上演時間は流儀・小書・演者によって大きく変わります。
> 確かめられる公演記録が揃うまで、目安の分数は載せません。

---

## 5. もったいぶらない

一覧の一文で、答えを伏せない。

```
悪い: 前半で女と別れ、後半でその同じ海から、自分が滅ぼした男が出てきます。
```

これは「何かが起きます」としか言っていない。
書き手は面白がらせているつもりだが、読者には情報が渡っていない。

伏せてよいのは、**記事本文が最後に答える問い**だけである。
一覧・要約・キャプションでは伏せない。

読者を引き込むのは、伏せることではなく、**具体を出すこと**である。
「十二、三歳の牛若丸」「白紙の巻物」「波の上から薙刀を構えて」。
固有名詞と数字と動作が、伏せ字より強い。

---

## 6. 文末と語順

- **です・ます**で書く。例外は記事冒頭の問いと、章の見出しだけ。
- **体言止めを使わない。**「橋の上の出会い。」ではなく「橋の上で出会います。」
- **倒置で余韻を作らない。**
- **短い断定を並べて「間」を作らない。**三文以上の短文連打を禁じる。
- 長めの一文で流れを作り、切りたいところだけ短くする。

「である」と「です・ます」を混ぜない。
一つの配列のなかで混在していた事故があるので、データファイルは特に注意する。

---

## 7. 見ていないものを書かない

`writing-style.md` の最上位規約を参照。ここでは文の形だけ繰り返す。

- 行っていない場所の体感を書かない（風、匂い、音、距離感）
- 観ていない上演の音や客席の反応を書かない
- 確認していない詞章を引用しない

現地取材をしていない場所には `FIELDWORK — 現地取材：未` を置く。

---

## 8. 書き終わったら通す点検

1. この一文だけを、何も知らない人が読んで、誰が何をしたか分かるか
2. 創作上の判断を、人ではないものの主語で書いていないか
3. 人名は初出でフルネームか。属性を添えたか
4. 死者を死者と書いたか
5. 数字に出典はあるか。丸い数字になっていないか
6. 体言止め・倒置・短文連打をしていないか
7. です・ますで揃っているか
8. 見ていないものを書いていないか

機械的に検出できる項目は `scripts/check-prose.mjs` が拾う。
拾えるのは 2・3・5・7 の一部だけなので、1 と 4 は目で見る。

```bash
node scripts/check-prose.mjs
```
